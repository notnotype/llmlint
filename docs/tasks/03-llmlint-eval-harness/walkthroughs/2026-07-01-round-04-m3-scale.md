## 起因

- **用户新增 ②**：用模型发现接口取 provider 当前可用模型（config.json 会过时），doubao 用 `Doubao-Seed-2.1-pro`。

## 改了什么

### A. 模型层（`generator/config.ts`、`model-client.ts`）
- **放宽 `resolveModel`**：provider 命中即用其连接（baseURL/apiKey/compat），**model-id 不在 `config.models` 列表内也放行**（用默认 context/maxTokens + 一条告警）。这样免改 neuro-book config 即可用发现到的新 id（如 `doubao-seed-2-1-pro-260628`）。新增 `resolveProvider`（只解析 provider 连接，供发现用）。
- **模型发现 `discoverModels`**：`GET {baseURL}/models`（OpenAI 兼容）列 provider 当前可用 id；`generate.ts --list-models <providerId>` 打印。失败（不支持/网络）返回空数组 + 告警，不阻断。
- `DEFAULT_MODELS` → 三家，doubao 用发现到的 `doubao-seed-2-1-pro-260628`。

### B. brief 详化（`generator/brief.ts`，v2）
- `BRIEF_SYSTEM` 升 v2：要更详细的**剧情内容**——场景/地点具体设定、每个出场人物身份/目标/关系、**细粒度**事件节拍（每个关键动作/转折/因果）、关键对话的**内容要点**、信息与悬念揭示时序、情绪转折点、叙述视角。`maxTokens` 2000 → 4000。
- **纪律不变**：仍**严禁**句子级文风/修辞/原文措辞（详化的是「发生了什么」，不是「怎么写的」）。理由：AI-vs-人的判别 tell 是**文体级**（破折号、量词、叠词…），详化 brief 只加**内容级**信息 → 更好地控住内容配对（正是 lift 想要的），只要不漏文体就不会压低 lift。
- 实测 round-04 brief 长度 879 / 1243 字（对比 v1 的过短），信息量明显上升。

### C. 逐章 1:1 配对（`generator/generate.ts` + `lib/metrics.ts`）
- generate：遍历题组**每个** reference → 各抽 `brief-<idx>.md`、各模型各写 `render-<idx>-<slug>.md`（targetChars = 本章字数）；meta render 条目加 `pairRef:"reference-<idx>.md"`。每模型重渲前按 slug 清旧 render（`clearRenderFiles` 兼容 round-03 单-brief 命名 `render-<slug>.md`），保留其它模型；作废 v1 单 `brief.md`。
- metrics `pairCountsByRef`：题组级 → 按 `pairRef` 逐章配对（reference-000X vs 挂它的 renders 比较率），`pairsTotal` 从 2（题组）升到逐章数。

### D. 稀疏判别器 prevalence + 分层 + holdout（`lib/{metrics,types,report,corpus}.ts`、`score.ts`）
- **prevalence**：每规则加 `aiFireFrac`/`humanFireFrac`（命中≥1 文档占比）+ `prevalenceLift = (aiFrac+β)/(humanFrac+β)`，β=0.1；`effectiveLift = max(rateLift, prevalenceLift)`，**裁决与排序都用 effectiveLift**（取较强桶）→ 稀疏 AI-only 规则不再被中位数埋没。原 `lift`（rate 口径）保留并列。
- **byGenre 分层**：`RuleStat` 加 `byGenre`（与 `byModel` 并列，共用 `StratRate` 类型）；report 加「跨题材一致性」列 = byGenre 里 lift≥3 的题材数 / 出现题材数。
- **holdout**：`score.ts --holdout <ratio>` 按 `genre/plotId` 排序**确定性**切题组（末尾 round(ratio·N) 组作 test）；规则/裁决只在 train 拟合，report 另报 train/test 两侧 docScore AUC（test 接近 train ⇒ 分离稳、非过拟；掉得多 ⇒ 不泛化）。题组 < 4（`HOLDOUT_MIN_GROUPS`）自动关闭并写警告——本轮 2 题组，holdout 代码就绪但默认关，等 M3-B 扩量启用（也让 round-03 移除的 `--holdout` 名副其实）。
- `corpus.ts` / `types.ts`：加载并透传 `pairRef`；`RuleStat` 加 prevalence/byGenre 字段，新增 `HoldoutStat`，`Report` 加 `holdout`。

### E. 单测扩（`lib/metrics.test.ts`）
- 加两例：① 「5 human 全 0 / 5 AI 里 2 篇命中(40%)」的稀疏规则 → 断言 `lift≈1`（rate 口径会误判 noise）但 `prevalenceLift≈5` 且 `verdict==="strong"`（证明 problem 2 修好）；② `pairRef` 逐章配对：两章 A/B，断言 `pairsTotal===2`、`pairsAiGreater===1`（证明逐章非题组级）。
- `bun test evals/lib/metrics.test.ts` → **7/7 通过**（5 原 + 2 新）。

### F. 生成鲁棒性（现场补，非原计划——首跑卡死后加）
- **背景**：首跑到 villain-0004 时 mimo 单次补全**挂起**，`resolved.timeoutMs`（6min）经 pi-ai 传下去对 xiaomi provider **不生效**，整条串行生成卡死 15min 无产出、无报错、无退出。
- **`model-client.callModel` 墙钟硬超时**：用 `Promise.race([completeSimple, setTimeout-reject])` 兜底，`min(timeoutMs, 240_000)`（正常补全 30-60s，4min 顶）→ 挂起即抛，不再无限阻塞。
- **`generate.ts` 逐篇容错 + 断点续跑**：render/brief 各包 try/catch（失败/超时/空输出**只跳这一篇**，不拖垮整轮）；render 按**文件存在跳过**（重跑复用已渲染，不重复调模型）；group 起始只清 round-03 旧命名 `render-<slug>.md`，保留逐章 `render-<idx>-<slug>.md`。重跑从断点补齐 17 render，不重做已完成的 10 篇。

### G. 静态 HTML 报告 + 复盘审查（收尾追加）
- **`lib/report-html.ts`（新）**：`renderHtml(report)` 出自包含单页 `report.html`（内联 CSS + 极简 vanilla JS，无外部依赖，浏览器直开）——AUC 进度条、docScore/误杀率卡片、模型条形榜（画人类基线竖线）、可**按表头排序 + 按裁决筛 + 搜规则名**的规则体检表（裁决色码、prevLift 高亮、配对 mini-bar）。`score.ts` 现同时写 json/md/**html** 三份。
- **全链路复盘（acquire→generate→consume→report）**：走查未发现 blocker。acquire 产出的 meta 是 corpus.ts 契约的干净超集（`title`/`author`/`sourceFile`/`pubYear` 写了但不消费，无害）；generate/consume 各接缝一致。**已清理（用户拍板）**：删掉 `generator/smoke.ts`（被 `generate.ts --check` 取代、无引用）；`evals/report/`（含 109KB `report.html`）加进 `.gitignore`（跑分产物可再生、每跑必 churn，对齐 `fixture-report/` 的忽略口径；corpus 仍进 git 不变）。**留观（低危，未改）**：① brief 抽取失败且该章已有 render 文件时，meta 会漏掉这些 render（仅「手删 brief 留 render」的非常态才触发）；② byGenre「跨题材」列用 rate-lift，prevalence-强规则恒显 0/2（M3-B ≥4 题材时让它纳入 prevalence）。

## 验证结果

**生成（逐章 1:1，3 模型，详化 brief）**：2 题组 × 5 章，reference 10 / render **27**（deepseek 10、mimo 10、doubao **7**）。doubao-2-1-pro 不稳：3 章空输出跳过（villain-0004、lotm-0001/0003）+ 2 章大幅欠长（327/709 字），其余正常。brief v2 长度 879–2087 字（对比 v1 过短），抽查无句子级文风泄漏（只列剧情/人物/节拍/信息时序）。

**单测**：`bun test evals/lib/metrics.test.ts` → **7/7**（含稀疏 prevalence、pairRef 配对两新例）。重构对旧语料回归一致（AUC 1.000、docScore 14.70/26.27），证明不破坏 round-03 口径。

**检测器（min-support 3，303 活跃规则 / 命中 123）**：
- **ROC-AUC 0.833**（round-03 是 1.000，但那建立在 4 render 的小样本清晰分离上不可信；37 样本的 0.833 才是可信数）。
- docScore 中位（去重 span/千字）：人类 **14.70** / AI **20.79**（round-03 AI 是 26.27 → 降，因 doubao 短/空 render 拉低 + 详化 brief 让 AI 内容更贴人类）。误杀基线 **4.27**（人类 agent 桶，与 round-03 同——同一批 reference）。

**模型排名（docScore 中位，越低越像人）**：doubao **14.71**（7）< deepseek **19.89**（10）< mimo **24.91**（10）。deepseek 比 mimo 更像人**复现 round-02/03**。⚠ doubao 榜首被**短/空 render 混淆**（7 样本含 327/709 字，短文本命中天然少），非「真更像人」，样本也偏小——记录在案，M3-B 补齐 doubao 覆盖后再评。

**prevalence 修好 problem 2（关键）**：top 强判别几乎都是 **rate lift≈1 但 prevLift 高**的稀疏 AI-only 规则——round-03 的中位 rate-lift 会把它们全判「噪声」丢掉，现在靠 prevLift 浮现：
- `cn.cliche.baguwen.dialogue-colon-to-comma`（agent，prevLift **7.67**，配对 **10/10**）——AI 每篇都犯、人类从不，最干净的 AI tell。
- `cn.modifier.measure.subject-measure-word`（prevLift 5.81）、`color-description.purple-dark-color-modifier`（4.33）、`action-expression.rough-manner-modifier`（4.33）、`cliche.trailing-sound-clause`（3.96）、`modifier.absolute-claim-modifier`（3.59）。
- rate 口径的老强判别仍在：`repeated-de-pairs`（叠词，lift 1.60 / prevLift 3.28，配对 10/10 强判别）、`dash-alone-to-comma`（破折号 lift 2.79）、`empty-quantifier`/`empty-measure`（量词 lift 2.64）。

**逐章配对修好 problem 3**：`pairsTotal` 从 round-03 的 2（题组级）升到**最多 10**（逐章）；强判别的 dialogue-colon、repeated-de-pairs 都 **10/10**（每章 AI 率都 > 人类），一致性远比题组级 1-2 有说服力。

**给 Task 02 的信号（复现前几轮）**：多条强 AI tell 落在 `human` 审查桶（`subject-measure-word`、`absolute-claim-modifier`、`repeated-de-pairs`），Agent 默认看不见 → Task 02 应据此上调路由或重审。

## 计划出入 / 局限

- **AUC 从 1.000 降到 0.833**：不是回归，是 round-03 的 1.000 建立在 4 render 小样本上不可信；扩到 27 render 后 0.833 才反映真实分离度。方向（deepseek>mimo 像人、量词/破折号/叠词领跑、baguwen 冒头）与前几轮一致。
- **doubao 数据质量拖累**：2-1-pro 在本任务上不稳（30% 空输出 + 偶发大幅欠长），既混淆它的模型榜（榜首含短文本 bias），也拉低整体 AI docScore。可能是新 key 配额/限流，或 2-1-pro 对版权网文剧情的安全过滤。M3-B 前需诊断（换 doubao 模型或重试补齐）。
- **prevalence β=0.1 小样本偏敏感**：min-support 1 时曾把强判别从 5 冲到 35；min-support 3 收敛到 7，说明 support 守门有效，但 β 仍是小样本初值，扩量后再校准（不预先过度调参）。
- **byGenre「跨题材」列用 rate-lift**：prevalence-强的规则跨题材恒显 0/2（它们 rate-lift≈1），与 effectiveLift 裁决口径不一致；2 题材下参考意义本就有限，M3-B（≥4 题材）让 byGenre 也纳入 prevalence 再看。
- **holdout 未启用**：2 题组 < 4，`--holdout 0.3` 实测自动关闭并写警告（代码/单测就绪），M3-B 扩题组后启用。
- **生成鲁棒性（本轮现场补，非计划内）**：首跑因 mimo 单次补全挂起（pi-ai 内部超时对 xiaomi 不生效）整轮卡死 15min。已加：`callModel` 墙钟硬超时（4min 顶）+ `generate.ts` 逐篇 try/catch 跳过 + **断点续跑**（按 render 文件存在跳过，只清 round-03 旧命名）。重跑从断点补齐 17 render 到齐，不重做已完成的 10 篇。这是「一次挂起拖垮整批且无法续跑」的系统性修复。

## Follow-ups（M3-B / 后续）

- **holdout 启用**：题材/题组扩到 ≥4 后开 `--holdout`，让裁决泛化性可测。
- **prevalence β 校准**：β=0.1 是小样本初值；扩量后按稀疏规则的真实分布校准，别预先过度调参。
- **抽取器自对齐 bias**：mimo 既抽 brief 又 render，扩量后考虑换独立抽取器或交叉验证。
